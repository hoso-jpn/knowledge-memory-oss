# Notion Knowledgeの入力と更新レビュー

Notionページ本文を編集正本、snapshotを取得証拠、Markdown/SQLiteを再生成可能な派生物とする。
添付Markdownは添付時点の控え。GitHubには実資料を転載せず、規約と架空例だけを置く。
Blogは公開用、Knowledgeは学習・判断・実務での再利用用とし、業務資料との境界は[プロファイル境界](profile-boundaries.md)で扱う。
この文書はNotionへの編集・ビュー追加・一括状態変更を実行しない。

## 最小入力と既存プロパティ

入口では題名と本文だけを優先する。原文の保存先や出典が分かれば添える。残りは整理時に補い、
不明値を推測で埋めない。既存mapping/1の8項目とNotion内蔵日時2項目を維持する。

| Notion | mapping/1または内蔵 | 整理時に扱う内容 |
| --- | --- | --- |
| Title | title | 内容を探せる題名 |
| 分野 | domain | 人が判断した主題。個人/業務の認証境界には使わない |
| 種別 | source_type | 原本の資料種別。記憶のkindを自動変更しない |
| 整理状態 | editorial_status | 人による整理作業の進捗 |
| 出典 | source_description | 原資料・章・発言者など。分からなければ空欄 |
| 出典URL | reference_url | 未検証の参照先。リンクがあるだけで検証済みにしない |
| 資料日 | document_date | 原資料の日付や版の日付 |
| 元ファイル | original_filename | 原資料のファイル名。files列へ置換しない |
| 作成日時 | source_created_at | Notion内蔵の作成日時 |
| 最終更新日時 | source_edited_at | Notion内蔵の編集日時 |

最後の2行は内蔵日時の役割を示すもので、表示プロパティ名をmappingに追加するものではない。
取得日時retrieved_at、出来事event_at、根拠確認verified_at、Web確認日も別物として本文に残す。
Webページを開いた日だけで全主張のverified_atを付けない。新しい必須列は追加しない。

## 本文テンプレート

[学習](../examples/knowledge-templates/learning.md)、[手順](../examples/knowledge-templates/procedure.md)、
[判断](../examples/knowledge-templates/decision.md)、[実験・失敗](../examples/knowledge-templates/experiment.md)は
全て架空例。必要な節だけを残し、空の節を埋めること自体を目的にしない。
各例は「原資料の説明」「観測」「本人の判断」「AIの適用案」を区別する。原文引用は変更しない。
訂正は引用の外へ追記し、誰が何を確認したかと未確認点を残す。

用語は「正式名 / 略語 / 和英別名 / 文脈 / 出典」を小さく持つ。原文の表記と検索用別名を分ける。
Notion本文の用語表やページリンクが、現行のaliases/related_idsへ自動変換されるとは限らない。
検索語候補を追加する場合は、導入前後の検索と回答の網羅性を別々に測る（[比較の方法](hybrid-search.md)）。
文脈固有の説明は各ページに残し、共通の用語集を無条件にコピーしない。主題別索引（MOC）には
参照リンク、現在の理解、未解決の問いを載せる。リンク先本文の正しさは別に確認する。

## 整理状態と更新レビュー

| 状態 | 人が残すもの | 次へ進む条件 |
| --- | --- | --- |
| 空欄 / 未整理 | 元の本文・分かる出典 | 整理を開始した |
| 整理中 | 主張の区別・不足している出典 | 必要な箇所と適用条件を確認した |
| 整理済み | 要点・根拠・条件・未確認点 | 更新理由が生じたら要更新へ |
| 要更新 | 新しい版・矛盾・期限などの理由 | 差分と影響を人が確認した |
| 保留 | 確認できない理由と次の条件 | 根拠や境界の問題が解決した |

これは規約案。存在しない選択肢やビューは別の変更一覧で反映する。
整理済みはactiveや真偽確認済みを意味しない。取り込みはcandidateのまま。

更新時は、(1)原資料の版と変更理由、(2)旧記述と新記述の差、(3)影響する手順/判断/関連ページ、
(4)残る限界、(5)確認者と確認日を記録する。競合した記録は片方を消して整合させず併記する。
派生Markdownだけを手修正せず、正本を人が編集した後に差分同期で確認する。
「要更新」「出典未記入」「分野別」は候補ビューで、空欄を隠して整理済み件数を増やさない。

## 実ページへ反映するとき

実ページの修正案は1ページずつ「対象、現在の箇所、変更案、根拠、変更後の確認、戻し方」を示す。
実本文の読み取り監査と具体的な差分がないページには、欠損・重複があると断定しない。
整理状態が未整理であることだけで低品質と判定しない。業務資料は個人用の境界と分けて扱い、
本文を個人用へコピーしない（[境界](profile-boundaries.md)）。
必要な新プロパティは任意性・mapping版・互換性・再取り込みへの影響を先に決める。
この文書の規約を採用しても、既存ページの本文は変更されない。
